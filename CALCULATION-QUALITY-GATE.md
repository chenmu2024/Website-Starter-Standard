# Calculation Quality Gate — P0 standard for tool-first sites

Scope: calculators, converters, measurement tools, price takeoffs, worksheet generators and any product where a numeric result changes a user's work. This is an engineering acceptance contract, not keyword/demand research. Apply with TRUST-AND-STRUCTURED-DATA-GATE.md and the owner-approved product scope.

## 1. Freeze the calculation contract

For each tool and each version, record:
- Inputs, units, datum/reference face, defaults and which parameters MUST be independent (e.g., backing-fabric width is not binding-fabric width).
- Output names, exact units, rounding/precision (compute with unrounded values and round only for display), allowable tolerances, and what CSV/SVG/PDF/print represents.
- Domain assumptions: actual vs nominal stock dimensions, kerf, fitting allowance, seam allowance, currency and exchange-rate policy, stock length, invalid values and impossible geometry.
- Safety and legal boundaries: geometry is not structural approval; time-sensitive tax/payroll rules require jurisdiction, source, effective date, refresh trigger and fallback.

A disclaimer cannot compensate for a wrong formula. User-entered or supplier-entered data must never be silently replaced by a guessed default.

## 2. Independent golden cases are mandatory

For EVERY tool, maintain at least one independently calculated and reviewed case of each kind:
1. normal — typical realistic input with manually or independently derived expected output;
2. boundary — zero or smallest permitted value, precision limit, material limit, rounding edge, or discontinuity;
3. invalid — forbidden geometry, unsupported units, missing value or other explicit error.

Store the expected output in a versioned golden-case JSON document. Put reference notes, equations, reviewed manual worksheet, published standard or independently developed calculation in an evidence file or URL. The evidence must truly support the case and cannot be generated by calling the same production function that is under test.

Schema: see templates/calculations/cases.example.json (illustrative fixture, NOT a woodworking validation certificate).

Each case includes:
- id, tool, kind, inputs;
- expected output fields and optional nonnegative per-field tolerance for valid inputs;
- expected_error code for invalid inputs;
- independent_reference.method and independent_reference.evidence.

The independent reviewer and physical testing status should be recorded in project release evidence. These textual assertions are a review requirement: a JSON validator cannot prove independence or physical correctness.

## 3. Compare against the real implementation, fail closed

The downstream site MUST have a test adapter that executes its production calculation engine against the golden inputs and writes actual output JSON. Do not import or call production calculation code to generate the golden expectations.

Run:

    python tools/validate_calculation_cases.py --cases tests/golden-cases.json --observed test-artifacts/observed-cases.json --output test-artifacts/calculation-audit.json

The program checks tool case-class coverage, metadata, exact case ID parity, result keys, errors, finite numbers and Decimal-based absolute tolerances. It fails on missing/extra results, wrong error codes, silent clamping, nonfinite outputs, mismatched data and unreviewed missing cases.

The following is useful during fixture drafting but IS NOT a calculation pass:

    python tools/validate_calculation_cases.py --cases tests/golden-cases.json --schema-only

Schema-valid alone is NOT release-ready. If the runtime adapter is missing or cases were not independently reviewed, mark NOT RUN and block claims of calculation correctness.

## 4. Properties and output contracts

Beyond golden cases, each project selects and documents relevant invariant/property checks, for example:
- Unit round trips preserve physical dimensions within declared tolerance (inch/foot/mm/cm/m).
- Monotonic material use when length/area increases, if this is mathematically true for the formula.
- Conservation of board length, area, piece count, cut allowance, or material purchase totals.
- No reuse of one independent input for an unrelated parameter. Test parameters separately and together.
- Numeric results agree with plotted SVG/Canvas geometry and labeled dimensions, not just a shared helper result.
- Exports (CSV/PDF/SVG/print) match visible results and preserve units, locale, sign and precision.
- Invalid input fails clearly; never convert NaN, overflow, negative or unbounded dimensions into a plausible successful result.
- Very large input sets remain bounded in memory/time and do not silently truncate critical output.

A property may not be universally true. Never enforce generic monotonicity where round-up, waste optimisation or layout changes invalidate it.

## 5. Physical measurement and specialist approval are separate

Paper ruler/printer calibration, material test cuts, real sewing, saw safety, teacher marking, regulated tax compliance and true device/screen-reader sessions require real evidence. Browser emulation and PDF rendering CANNOT certify physical dimensions.

Record for every release separately:
- AUTOMATED VERIFIED, HUMAN VERIFIED, NOT RUN, FAIL, or NOT APPLICABLE;
- tested material/device, measurement tool and source, date, reviewer, expected vs observed measurements and acceptance tolerance;
- links to reproducible outputs and photos if legitimately obtained.

Never convert a user self-check into independent approval; block an affected high-risk feature until the required specialist or physical review is recorded.

## 6. Release decision

P0: core formula wrong, safety-critical false result, silent bad input acceptance, or data corruption → BLOCK.
P1: missing normal/boundary/invalid goldens for a released calculator, unexecuted production engine comparison, relevant false units/rounding, or wrong export parity → BLOCK relevant release.
P2: helpful additional cases or improvements outside approved scope → document and prioritise.

A successful build, raw HTML scan, Lighthouse score or high GEO score is not a substitute for independent numeric test evidence.
